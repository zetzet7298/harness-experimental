# Design

## Domain Model

- `EquipmentCatalog` contains generated VHCND equipment rows, quality, source metadata, base attributes, magic attributes, requirements, slot mapping, and visual candidate metadata.
- `InventorySnapshot` now carries equipped IDs, equipped item objects, bag IDs, the full catalog, and derived stats.
- `CharacterStats` stores supported aggregate values such as strength, dexterity, HP, mana, physical damage, defense, move speed, and elemental/poison/all resist values.

## Application Flow

1. `scripts/vltk-normalize-equipment-index.py` decodes active VHCND tables and option references.
2. `scripts/vltk-build-equipment-seed.py` writes `src/data/equipmentCatalog.json` and `src/data/inventory.json`.
3. `EquipmentScene` loads catalog/profile data, validates equip attempts, writes `vhcnd-equipment-state-v1` to `localStorage`, and starts the run.
4. `offlineGateway.getInventory()` rebuilds the runtime inventory from persisted equipment or seed defaults.
5. `GameScene` starts with that inventory and selects an approved wardrobe visual combo when equipped head/body resources map to generated combo sheets.

## Interface Contract

- Runtime persistence key: `vhcnd-equipment-state-v1`.
- Bag policy: `one-equipment-per-mobile-cell`.
- Equipment slots remain the VHCND equip-slot set, with two ring slots represented as `ring1` and `ring2`.

## Data Model

- No database changes.
- Generated JSON files live in `game-source/src/data/` and can be regenerated by scripts.
- Large generated catalog data should not be hand-edited.

## UI / Platform Impact

- `PreloadScene` now starts `EquipmentScene` first.
- Equipment screen is a portrait Phaser scene with slot buttons, stats/detail panel, bag grid, equip/unequip, and run action.
- Bag items occupy one mobile cell regardless of legacy PC item width/height.

## Observability

- HUD displays equipped weapon, physical damage, defense, poison/all resist, and count of unsupported equipment attributes.
- Validation report records test/build commands and known formula/visual gaps.

## Alternatives Considered

1. Prebuild all visual combinations: rejected for now because build/runtime size is too high without preview approval for each combination.
2. Keep equipment as fixtures: rejected because the request requires full PC slot/catalog coverage and easy test seed data.
